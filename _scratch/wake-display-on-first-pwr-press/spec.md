# Wake Display on First PWR Press

Status: ready-for-agent

## Problem Statement

设备因闲置自动进入 Display Off 后，第一次短按 PWR 没有点亮屏幕，需要再次短按才能恢复显示。

PWR 手动熄屏后的唤醒目前正常。问题仅在自动熄屏路径出现。设备并未关机或重启，计时仍在继续。

## Solution

自动熄屏后，第一次有效的 PWR 短按必须可靠地唤醒显示、恢复用户选择的正常亮度，并从该时刻重新计算闲置时间。

不得丢弃已经从 PMIC 读取到的短按事件。现有手动熄屏、长按关机、触摸唤醒和计时行为保持不变。

## User Stories

1. 作为设备用户，我希望自动熄屏后第一次短按 PWR 就能点亮屏幕，以免重复操作。
2. 作为设备用户，我希望 PWR 唤醒后恢复所选正常亮度，以便立即看清界面。
3. 作为设备用户，我希望 PWR 唤醒后重新计算闲置时间，以免屏幕立即再次变暗。
4. 作为设备用户，我希望 PWR 手动熄屏后仍能第一次短按唤醒。
5. 作为设备用户，我希望屏幕亮着时短按 PWR 仍能关闭显示。
6. 作为设备用户，我希望 PWR 只控制显示时不会中止或重置当前计时。
7. 作为设备用户，我希望 Display Off 期间 Pomodoro deadline 继续正常推进。
8. 作为设备用户，我希望长按 PWR 的关机行为保持不变。
9. 作为设备用户，我希望触摸熄屏唤醒规则保持不变。
10. 作为设备用户，我希望完成计时自动唤醒显示的行为保持不变。
11. 作为维护者，我希望已识别的 PWR 短按不会因暂时无法取得 UI 锁而永久丢失。
12. 作为维护者，我希望修复集中在现有显示生命周期和硬件动作入口，不引入通用事件系统。
13. 作为维护者，我希望失败的动作可以安全重试，但一次物理短按最多切换显示一次。
14. 作为维护者，我希望 Pomodoro、Pomodoro Set、统计和持久化规则不受影响。

## Implementation Decisions

- Display Off 指显示面板关闭，但设备、应用和计时继续运行。
- 自动熄屏和 PWR 手动熄屏共享同一显示状态语义。
- 显示关闭时，PWR 短按执行唤醒；显示开启时，PWR 短按执行熄屏。
- 唤醒恢复用户当前选择的正常亮度，并将闲置计时起点更新为唤醒时刻。
- 首先确认自动熄屏后的首次短按是否产生 `Hardware action lock timed out`。
- 若确认硬件动作因 UI 锁竞争而丢失，应在现有硬件动作入口保留并重试待处理的 PWR 动作，而不是延长阻塞时间或建立通用事件总线。
- PMIC 事件已清除但尚未成功分发时，软件必须保留对应的待处理动作。
- 重试必须保证一次短按只执行一次显示切换。
- 不改变 PWR 长按优先级和关机行为。
- 不改变触摸输入、显示调暗阈值或 Running 状态的显示策略。
- 不新增设置、依赖、持久化字段、领域术语或 ADR。

## Testing Decisions

- 最高自动化测试缝为现有 application orchestrator。
- 增加组合回归场景：Ready 状态闲置 300 秒自动熄屏，然后分发一次 PWR 短按对应动作。
- 验证第一次动作后显示已开启、亮度恢复为用户选择值且 timer state 未改变。
- 验证唤醒后 119 秒仍保持正常亮度，120 秒后按现有策略调暗。
- 保留并复用现有手动熄屏/唤醒、触摸唤醒、完成唤醒及长按关机测试。
- 自动化测试只断言外部可观察结果，不断言私有字段或回调顺序。
- 不建立新的 LVGL 主机测试框架。
- 运行完整 C 主机测试套件和 ESP-IDF 固件构建。
- 目标设备验证必须覆盖：
  - 自动熄屏后第一次短按 PWR 立即点亮；
  - 连续多次重复该流程，每次均无需第二次短按；
  - 手动熄屏后的首次短按仍可唤醒；
  - 屏幕亮着时短按仍可熄屏；
  - Running timer、触摸唤醒、完成唤醒及长按关机不受影响；
  - 监视日志中不再出现导致 PWR 动作丢失的锁超时。

## Out of Scope

- 修改两分钟调暗或五分钟熄屏阈值。
- 修改 Running 状态的 60% 亮度规则。
- 修改触摸唤醒及首次触摸消费规则。
- 修改 PWR 长按关机行为。
- 修改 PMIC、显示控制器或板级硬件配置。
- 新增输入框架、事件总线、任务队列或用户设置。
- 修改 Pomodoro 状态机、统计或持久化规则。

## Further Notes

当前 application orchestrator 分别覆盖了自动熄屏和 PWR 手动切换，但缺少“自动熄屏后首次 PWR 短按”的组合回归场景。

设备平台会先读取并清除 PMIC 事件，再尝试获取 LVGL 锁。锁获取失败时动作会被直接丢弃，这是首要验证的潜在根因；在日志或实机证据确认前，不应猜测性修改显示策略。
