# Restore Brightness on Any Touch

Status: ready-for-agent

## Problem Statement

屏幕因闲置进入变暗状态后，当前只有触发 UI 动作的触摸才会恢复亮度。点击空白区域或开始某些手势不会被记录为交互，导致屏幕继续保持暗态，与“触摸屏幕应立即变亮”的用户预期不符。

同时必须保留现有熄屏保护：屏幕完全关闭时，第一次触摸只能唤醒显示，不能意外执行底层按钮或手势。

## Solution

将所有有效屏幕接触统一视为用户交互，并在 LVGL 输入设备的按下边界处理：

- 屏幕亮着但已变暗时，立即恢复用户选择的亮度、重置闲置计时，并继续执行当前按钮或手势。
- 屏幕完全关闭时，第一次接触恢复亮度，但消费整次接触；释放后用户才能进行下一次操作。
- 空白区域、按钮和滑动起点采用相同规则。

## User Stories

1. 作为设备用户，我希望点击屏幕任意位置都能恢复亮度，以便无需寻找特定按钮。
2. 作为设备用户，我希望点击空白区域也能恢复亮度，以便触摸行为符合直觉。
3. 作为设备用户，我希望在屏幕变暗时点击按钮能够同时恢复亮度并执行操作，以免需要点击两次。
4. 作为设备用户，我希望在屏幕变暗时开始滑动能够恢复亮度并正常完成手势。
5. 作为设备用户，我希望触摸后恢复用户选择的主亮度，以便界面立即清晰可见。
6. 作为设备用户，我希望触摸后重新计算闲置时间，以免屏幕刚恢复就再次变暗。
7. 作为设备用户，我希望 Running、Ready、Paused 和 Completion Transition 使用相同的触摸恢复规则。
8. 作为设备用户，我希望熄屏后的第一次触摸只唤醒显示，以免误触底层按钮。
9. 作为设备用户，我希望熄屏唤醒触摸不会触发滑动、点击或数值修改。
10. 作为设备用户，我希望第二次触摸能够正常操作，以便唤醒后立即继续使用。
11. 作为设备用户，我希望一次按钮触摸只执行一次动作，以免恢复亮度造成重复操作。
12. 作为维护者，我希望在统一输入边界处理触摸，以免逐个控件维护唤醒逻辑。
13. 作为维护者，我希望现有 Pomodoro、Pomodoro Set、统计和持久化规则保持不变。

## Implementation Decisions

- 将 LVGL 输入设备的按下事件作为所有触摸交互的统一入口，而不是为每个控件增加处理器。
- 复用现有应用触摸处理接口，作为恢复亮度、重置闲置时间及判断是否消费触摸的唯一应用级逻辑。
- 屏幕仍亮但已变暗时，触摸不被消费；LVGL 继续向目标控件分发当前事件。
- 屏幕完全关闭时，应用返回“已消费”，平台要求输入设备等待本次接触释放，从而阻止点击、手势及底层动作。
- 动作分发层不再重复记录同一次物理触摸。
- 触摸恢复至用户当前选择的亮度，并从触摸时刻重新计算两分钟调暗和五分钟熄屏阈值。
- Running 的既有 60% 调暗规则保持不变；其他状态的 Idle brightness 与熄屏规则保持不变。
- 实体按键和计时 Tick 不伪装成屏幕触摸。
- 不增加事件总线、通用输入框架、新依赖、持久化字段或设置项。
- 不新增领域术语或 ADR。

## Testing Decisions

- 最高自动化测试缝为现有应用触摸接口和 application orchestrator 测试。
- 自动化测试应验证外部可观察行为，不断言 LVGL 对象、私有字段或回调顺序。
- 扩展现有显示生命周期测试，验证：
  - Ready 状态达到调暗阈值后处于低亮度；
  - 触摸不被消费；
  - 触摸立即恢复用户选择的亮度；
  - 触摸后不足 120 秒时保持主亮度；
  - 触摸后达到 120 秒时再次按既有策略调暗；
  - 熄屏后的第一次触摸仍被消费并恢复亮度；
  - 第二次触摸不再被消费。
- 复用现有 Running 调暗、完成唤醒及熄屏首触消费测试，不建立新的 LVGL 主机测试框架。
- 运行完整 C 主机测试套件和 ESP-IDF 固件构建。
- 在目标设备上验证：
  - 调暗后点击空白区域恢复亮度；
  - 调暗后点击按钮恢复亮度且动作只执行一次；
  - 调暗后滑动恢复亮度且手势正常；
  - 熄屏后在按钮位置触摸只唤醒；
  - 熄屏后的触摸不会产生点击、滑动或数值变化；
  - 第二次触摸正常执行操作；
  - 四种 UI Orientation 下行为一致。

## Out of Scope

- 修改两分钟调暗或五分钟熄屏阈值。
- 修改 Running 的 60% 亮度规则。
- 修改 Idle brightness 设置范围或默认值。
- 新增“首次触摸只变亮”的偏好设置。
- 修改实体 PWR、音量键或自动完成唤醒行为。
- 修改 Pomodoro 状态机、统计、持久化或导航规则。
- 引入新的输入框架或 LVGL 自动化测试框架。

## Further Notes

现有应用逻辑已经能够恢复亮度、重置闲置时间并消费熄屏后的首次触摸。缺口位于设备输入接缝：空白触摸不会触发 UI 动作，因此没有到达该逻辑。修复应集中在统一触摸入口，而不是散布到各个控件。
