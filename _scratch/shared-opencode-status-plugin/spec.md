# Shared OpenCode Status Plugin with Process Selection

Status: ready-for-agent

## Problem Statement

当前 OpenCode Status 插件位于 Pomodoro 仓库的项目级 `.opencode/plugins/`，只在该项目加载。用户有多个 OpenCode 进程（不同项目）同时运行时，设备只能显示运行在 Pomodoro 项目中的那个进程的状态；在其他项目里打开的 OpenCode 不加载插件，即使它正在 Waiting、Working 或 Error，设备也无从得知。每次在别的项目使用 OpenCode 时，状态圆点就失去意义。

插件代码也随项目仓库复制，无法在用户级共享和维护。

## Solution

把 OpenCode Status 插件从项目级迁移到用户级，让所有 OpenCode 进程、所有项目共享同一份插件。多个 OpenCode 进程并存时，通过“显式选择 + 自动回退”的协调机制确定唯一的状态来源：第一个加载插件的进程自动成为所选进程，后续进程不抢占；用户在目标 OpenCode 中执行 `/pomodoro-select` 即可把状态来源切换到当前进程；所选进程退出后自动回退到仍存活的最早进程。设备继续只显示所选进程当前项目内全部会话的聚合状态。

进程切换总是开启新的状态周期（新 revision、唤醒屏幕、清除旧来源的本地确认）。USB 烧录保留也迁到用户级，使任何项目下选中的进程都能与 `tools/flash.sh` 协调释放串口。

## User Stories

1. 作为用户，我希望在任何项目的 OpenCode 中都能看到设备上的状态圆点，所以我不必回到 Pomodoro 项目才能使用状态指示器。
2. 作为用户，我希望所有 OpenCode 进程共享同一份插件实现，所以插件只在一个地方维护。
3. 作为用户，我希望第一个加载插件的 OpenCode 进程自动成为状态来源，所以设备在只有一个进程时无需任何配置就能工作。
4. 作为用户，我希望后续启动的 OpenCode 进程不抢占状态来源，所以已选中的进程不会被我顺手打开的另一个项目打断。
5. 作为用户，我希望在某个 OpenCode 中执行 `/pomodoro-select` 后，设备立即改显那个进程的状态，所以我可以主动决定哪个进程反映在设备上。
6. 作为用户，我希望选择命令只切换状态来源，不改变 Timer、Pomodoro Set、Statistics 或其他设备行为。
7. 作为用户，我希望所选进程退出后设备自动回退到仍存活的最早进程，所以状态指示器不会因为一个进程关闭而长期断开。
8. 作为用户，我希望进程切换总是开启新的状态周期，所以即使新旧进程聚合出的颜色相同，设备也立即刷新并唤醒屏幕。
9. 作为用户，我希望切换进程不会把上一个进程的未确认 Error 或 Completed 状态带过来，所以新来源从干净状态开始展示。
10. 作为用户，我希望只有当前所选进程能占用 USB 串口，所以多个进程不会互相抢端口。
11. 作为用户，我希望所选进程可能属于任意项目时也能安全烧录固件，所以 USB 保留机制不依赖项目内文件。
12. 作为用户，我希望保留释放后状态通信自动恢复，所以烧录完固件不需要我重启 OpenCode。
13. 作为用户，我希望烧录保留的超时、失败和中断清理语义保持不变，所以安全烧录保证不因迁移而退化。
14. 作为用户，我希望新进程的聚合状态变化仍按原有优先级（Error > Waiting > Working > Completed > Idle）显示，所以迁移不改变既有状态语义。
15. 作为用户，我希望设备设置 Off/On、拔插、串口占用与静默重连行为保持不变，所以迁移不破坏已验收的集成行为。
16. 作为用户，我希望设备不会把其它进程的会话内容（标题、提示词、代码、回复、错误详情）发到串口，所以隐私边界不因多进程支持而改变。
17. 作为用户，我希望状态目录不可用时插件 fail closed 且不打开串口，所以异常环境下不会出现两个进程同时写同一个设备。
18. 作为用户，我希望短暂存活的辅助进程（如一次性命令）退出后自动回退不会造成抖动，所以偶发进程不会频繁打断当前显示。

## Implementation Decisions

### 迁移与部署

- 插件实现从 Pomodoro 仓库 `.opencode/plugins/` 迁至用户配置仓库，作为全局插件加载；Pomodoro 仓库不再包含插件文件，避免同一插件被加载两次。
- 插件不引入 npm 依赖，不建立额外服务；只使用 Node 内置能力与 macOS `/dev/cu.usbmodem*` 设备文件。
- `/pomodoro-select` 作为全局命令提供；插件通过 `command.execute.before` hook 拦截并在当前进程上执行选择，用 Toast 与简短会话回复给出成功反馈。
- 所有加载该用户插件的 OpenCode 进程都参与协调，不区分交互式 TUI 与一次性 CLI（插件 API 没有稳定标志，不依赖脆弱的启动参数猜测）。

### 用户级运行状态目录

- 所有进程共享一个用户级运行状态目录，位于 `${XDG_STATE_HOME:-$HOME/.local/state}/opencode/pomodoro-status/`，不含任何项目内容或会话内容。
- 该目录保存：每进程实例记录（随机实例 ID、PID、启动时间、心跳）、当前所选进程（原子写 + 短期文件锁）、全局 revision 计数、USB 烧录保留标记。
- 目录不存在且无法创建时 fail closed：插件保持不连接、不竞选、不写状态，只在目录可用后恢复。
- 存储不可靠（写失败、锁超时）时同样 fail closed，保证任意时刻至多一个进程持有串口。

### 多进程协调

- 第一个成功注册的实例自动成为所选进程；后续实例注册但不抢占。
- `/pomodoro-select` 把选择原子替换为当前进程，并总是开启新的状态周期。
- 所选进程的心跳超时或显式退出后，剩余实例按启动时间回退到最早的存活实例；无存活实例则断开等待。
- 短暂存活的辅助进程会注册并可能在退出后触发一次回退，但回退目标是仍在运行的最早进程，不会造成状态抖动；不引入“最小存活时长”之类的启发式。
- 只有所选进程可以打开 USB 串口并发送心跳；非所选进程持续聚合事件但不发送。

### 全局 revision

- 全局 revision 在用户级状态目录中单调递增，跨进程共享；来源切换和所选进程的聚合状态变化都会递增。
- 心跳保持同一 revision；ACK 只清除与当前已发布 revision 匹配的 Error 或 Completed。
- 来源切换即使新旧聚合颜色相同也分配新 revision，使设备立即刷新、清除旧来源的本地确认并唤醒。
- 设备固件的协议解析与显示逻辑不因迁移而改变；revision 比较、Completed 五秒到期、十秒心跳超时等既有规则继续生效。

### 全局 USB 烧录保留

- 保留文件迁移到用户级状态目录；`tools/flash.sh` 与所有插件实例使用同一路径。
- 保留期间所有插件实例不得竞选或打开串口；保留释放后自动恢复选举与连接。
- 保留写入 PID、存在且 PID 存活时视为持有；PID 失效或文件移除即释放。
- `tools/flash.sh` 保持超时等待、成功/失败/中断统一清理、绝不向 OpenCode 进程发送信号的既有保证。

### 领域模型

- `CONTEXT.md` 增加 **OpenCode Process**（一个独立运行的 OpenCode 实例，含其当前项目内全部会话）与 **Selected OpenCode Process**（当前向设备提供聚合状态的唯一 OpenCode Process），并更新 **OpenCode Status** 的定义以反映单进程来源与显式选择/自动回退语义。

## Testing Decisions

### 测试接缝

只保留一个纯 Node 核心接缝：把事件映射、多会话聚合、进程仲裁、全局 revision 与保留协议做成无硬件依赖的纯模块，沿用现有 `check-opencode-status.mjs` 的 assert 风格可运行检查。插件接线层（串口、定时器、文件系统、OpenCode hook）保持薄层，不单独测试；通过端到端验收覆盖。

### 核心检查覆盖

- 首实例自动成为所选进程，后续实例不抢占。
- `/pomodoro-select` 原子切换、开启新状态周期并给出反馈。
- 所选进程心跳超时或退出后回退最早存活实例；无存活实例时断开。
- 过期实例记录清理与并发竞选唯一性。
- 任意时刻至多一个实例持有串口（竞选 + 保留的互斥）。
- 来源切换与聚合状态变化递增全局 revision；心跳 revision 稳定。
- 旧进程较小的 revision 不触发设备回归（由新来源的新 revision 周期保证）。
- ACK 只作用于当前已发布 revision。
- 全局烧录保留的获取、释放、PID 失效与恢复。
- 原有事件映射、优先级聚合、端口发现、enable/disable 与心跳行为不回归。

### 集成验收

- 两个不同项目的 OpenCode 同时运行：设备显示所选进程的聚合状态；`/pomodoro-select` 切换后设备立即刷新并唤醒。
- 同色切换也开启新状态周期；未确认状态不跨进程继承。
- 所选进程退出后自动回退到最早存活进程并恢复显示。
- 从 Pomodoro 仓库烧录固件时，即使所选进程属于其他项目也能释放串口，保留释放后自动重连。
- 设置 Off/On、拔插、串口占用、四种 UI Orientation 与既有验收点不回归。
- 用户配置仓库测试、Pomodoro host tests 与固件构建全部通过。
- 配置变更后完全退出所有 OpenCode 进程再重启，执行交互式验收。

## Out of Scope

- 在设备上选择 OpenCode 进程或显示进程列表。
- 一次向设备合并多个 OpenCode 进程的聚合状态。
- 跨机器或远程 OpenCode 支持。
- Windows 与 Linux 串口发现。
- 修改 OC1 线路协议或设备固件的解析/显示规则。
- 改变 Pomodoro Timer、Pomodoro Set、Statistics 或完成提示规则。
- 为插件引入 npm 依赖、后台服务或网络端点。
